# GitHub profile scorecard — 10 points

Use this before sharing your GitHub profile with classmates, recruiters, collaborators or online communities.

Give yourself **1 point** for every statement that is true.

## Score yourself

- [ ] **Clear identity** — my name or preferred developer identity is obvious in the first screen.
- [ ] **Clear focus** — a visitor can tell what I build or what area I am learning in one sentence.
- [ ] **Focused stack** — I show technologies I actually use, not every tool I have ever tried.
- [ ] **Proof of work** — at least one project is easy to find from my profile.
- [ ] **Useful project description** — featured projects explain the problem, result or learning value.
- [ ] **Readable layout** — headings, spacing and badges help scanning instead of creating clutter.
- [ ] **Working links** — portfolio, LinkedIn, ORCID or project links work and are current.
- [ ] **Safe public content** — no secrets, private data, client code or sensitive school material is exposed.
- [ ] **Recent activity** — at least one public repository or profile element reflects what I am doing now.
- [ ] **Memorable value** — there is at least one useful repo, resource, template, demo or project worth revisiting.

## Your result

| Score | Interpretation | Next move |
| ---: | --- | --- |
| **0–3** | The profile is difficult to understand quickly. | Start with the 60-second template and add one real project. |
| **4–6** | The basics are there, but the profile still feels generic. | Improve positioning, project descriptions and visual hierarchy. |
| **7–8** | Strong and shareable. | Remove clutter and strengthen your best public project. |
| **9–10** | Clear, credible and easy to scan. | Keep it current and build useful public work consistently. |

## Fast fixes by problem

**My profile feels empty**  
Use [`../templates/profile-readme-60s.md`](../templates/profile-readme-60s.md) and feature one project.

**My profile has too many badges**  
Keep only the technologies you can discuss or demonstrate in a project.

**Most of my work is private**  
Use [`public-repo-ideas.md`](./public-repo-ideas.md) to publish a generic demo, learning resource or reusable template instead of private source code.

**My projects look like school exercises**  
Rewrite the descriptions around the problem solved, decisions made and what someone else can learn or reuse.

**I want my public repo to be easier to star**  
Use [`launch-plan.md`](./launch-plan.md) and make the value obvious before asking anyone to star it.

---

A GitHub profile does not need to be perfect. It needs to be **specific, credible and easy to understand quickly**.
