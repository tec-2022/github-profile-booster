# Community Showcase 🌟

Profiles improved with **GitHub Profile Booster** can be featured here.

The goal is simple: show real, public examples so students and junior developers can see different ways to present their work without copying one identical layout.

## Want to be featured?

1. Use the [Career Signal Map](https://tec-2022.github.io/github-profile-booster/career-map.html), [Goal Comparison](https://tec-2022.github.io/github-profile-booster/compare-goals.html), [Goal-Aware Optimizer](https://tec-2022.github.io/github-profile-booster/optimizer.html), [README Generator](https://tec-2022.github.io/github-profile-booster/generator.html), one of the [templates](./templates), or the [Profile Audit](https://tec-2022.github.io/github-profile-booster/audit.html) to improve your profile.
2. Make sure your profile README contains no secrets, private information, school-sensitive data, client data, or code you do not have permission to publish.
3. [Open a **Showcase submission** issue](https://github.com/tec-2022/github-profile-booster/issues/new?template=showcase.md).
4. Share your public GitHub username, target direction, and what changed.
5. If useful, include a shareable Career Map / Goal Comparison / Optimizer URL so the evidence can be reproduced.

> A submission is an invitation to review the public profile for possible inclusion. It does not guarantee placement.

## What makes a useful showcase example?

A good example usually has:

- A clear first-screen introduction.
- A focused technology stack.
- At least one proof-of-work project.
- Readable visual hierarchy.
- Public information only.
- Its own personality instead of looking like an untouched template.
- A short explanation of the target direction and why specific repositories were featured.

## What a before/after story should show

A strong future Showcase entry should document three stages:

1. **Before:** what the profile appeared to communicate.
2. **Decision:** what direction the user wanted to reinforce and what the tools surfaced.
3. **After:** what changed in the README, featured repositories, descriptions or public proof.

## Why a showcase?

Templates help people start. Real examples help them make better choices.

The showcase is intentionally community-driven and will only list external profiles whose owners submit them voluntarily. No fake testimonials or invented users.
